# Agent Object Model audit 001, 2026-11-10

Uptime Kuma 2.5.9, at http://localhost:3000, as `admin` (and the sign-in screen as a signed-out visitor). 26 pages, 169 screens (the rows of "Screens covered"; three of them stand for many: 32 monitor types, 105 notification types, 9 push example languages).
52 failures (24 at level A, 25 at AA, 3 at AAA), 0 possible problems in the Agent Object Model.

How to read this: the app embeds no projector and carries no `data-agentom-*` markup, so every page was read through the audit's own projector with default options. Each finding is one cause, with every page and element it was seen on. "Key" is the element as `agent-om check` names it; "(node)" is a node id from `agent-om view`; a CSS selector is given where the element has no node. A fix is markup only: nothing a person sees or does changes.

Where a screen showed what looks like a secret, the developer said which are secrets: a push monitor's token (F-051), the new API key (F-020) and the plain credential fields (F-021) are; the help text the check flagged in three places isn't ("Looked at"). The push monitor's screens, held back for that answer, were then checked.

## Findings

### F-001 1.1 Native semantics first (A)

- **Page:** every signed-in page (the header)
- **Element:** `div.nav-link`
- **Found by:** `lost-control` (a review, judged a failure)
- **What's wrong:** the profile menu (Maintenance, Settings, Help, Log out) opens from a `div` with `data-bs-toggle="dropdown"`. It has no role, so it is no node: the projection shows only the loose text "A". An agent has no way to open the menu, and so no way to reach Maintenance, Settings or Log out from the page.
- **Evidence:** `review 1.1 div.nav-link: pointer cursor, no node: a control?`; `src/layouts/Layout.vue` line 50: `<div class="nav-link" data-bs-toggle="dropdown">`. The menu had to be opened with `--selector ".dropdown-profile-pic .nav-link"`. Open, its items are nodes.
- **Fix:** make the same element a button in markup: `role="button" tabindex="0" aria-haspopup="menu" aria-label="Account menu"` (Bootstrap already sets `aria-expanded` on it once used), or a `<button>` styled as it is now.
