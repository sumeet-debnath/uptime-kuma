# Agent Object Model audit 001, 2026-11-24

Uptime Kuma 2.5.9 (production build with seeded monitors, status pages and maintenance), at http://127.0.0.1:3610, as admin. 28 pages, 137 screens.
56 failures (32 at level A, 22 at AA, 2 at AAA), 2 possible problems in the Agent Object Model.

## Findings

### F-001 1.1 Native semantics first (A)

- **Page:** every signed-in page at desktop width (the header)
- **Element:** `div.nav-link in banner`
- **Found by:** `lost-control` (review, judged a failure)
- **What's wrong:** the account menu's trigger (the "A" avatar and chevron) is a `div` with a click handler from Bootstrap's dropdown. It opens the only way to Maintenance, Settings, Help and Log out, and an agent sees it only as `clickable "A"`, with no role, no name that says what it is, and no state.
- **Evidence:** `<div class="nav-link show" data-bs-toggle="dropdown" aria-expanded="true">`; Chrome reads it as `generic` with no name; the view shows `clickable "A"`. Its `aria-expanded` is dropped because the element has no role.
- **Fix:** on the same `div`: `role="button"` and `aria-label="Account menu for admin"`. Keep its `aria-expanded`, which Chrome then reads. No `tabindex` (keyboard access stays as it is). What it offers: F-044.

- **Found by:** `lost-control`
- **What's wrong:** the choices of the Status filter (Up, Down, Pending, Maintenance, Running, Paused) and of the Tags filter (Env, Team, Region, Legacy, Prod) are `div`s with click handlers. An agent reads `clickable "Down4"`: no role, no checked state, the count run into the name.

On the `ul.filter-dropdown-menu` around them: `role="menu"` and `aria-label="Filter by status"` / `"Filter by tag"`.

## Possible problems in the Agent Object Model

### P-001 `view` can't show a native select's full choices

- **Page:** /add, /edit/{id} (Monitor Type, 32 options); /settings/general, /maintenance/edit/{id} (Timezone, 300+)
- **Element:** `combobox "Monitor Type"` (node)
- **Found by:** reading the screen
- **What's wrong:** the view cuts the choices ("… 18 more (scope e27146 limit 0)") and tells you to use `limit 0` on the node; `agent-om-audit view e27146 --limit 0` and `view --limit 0 e27146` both print the same cut line. The markup is a plain `<select>` with every `<option>`.
- **Evidence:** the same "… 18 more" after each variant.
- **Fix:** in the view (not the app): honour `--limit 0` for a node's choices, or say how to see them.

### P-002 A required field left empty reads as valid after a submit

- **Page:** /edit/{id}
- **Element:** `textbox "URL"` (node)
- **Found by:** reading the screen
- **What's wrong:** after emptying the required URL field and pressing Save, the browser refused the submit (its own message, not in the page), but Chrome's tree says `invalid: "false"` and the view shows only `required`. The guidelines count a field the browser's validation rejects as invalid. Not verified: Chrome may report `invalid` only after the user edits the field (`:user-invalid`), and the audit's `type ""` may not count as an edit.
- **Evidence:** `agent-om-audit inspect`: `"states":{"invalid":"false",…,"required":true}`, markup `<input id="url" type="url" pattern="https?://.+" required>`.
- **Fix:** check how Chrome sets `invalid` for native constraint validation and whether the projection should report it.
